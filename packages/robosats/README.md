# robosats

Pure-Dart RoboSats client primitives for Troc: the robot identity and OpenPGP key (see the library comment of `lib/robosats.dart`), and the read-only client of the coordinators described below.

## Coordinator client (read-only)

- `Federation.robosats` is the federation list embedded from RoboSats `federation.json` (commit ff1998c): each `Coordinator` has its aliases, description, contact, badges, policies, onion addresses and Lightning node keys per `RobosatsNetwork`. `RobosatsCurrency` maps the RoboSats currency ids to codes. Both are generated by `tool/generate_coordinator_data.dart`.
- `CoordinatorTransport` is the port the app implements over Tor in `features/p2p`: one HTTP request in (`CoordinatorRequest`: method, absolute onion URL, headers, body, the largest body accepted), one `CoordinatorResponse` or a `CoordinatorTransportFailure` out. The adapter owns sessions, deadlines, retries and the `User-Agent`, and must not follow redirects.
- `CoordinatorClient(transport)` reads one coordinator: `fetchInfo` (`/api/info/`, whose `network` and `node_id` are checked against the federation entry by `Coordinator.verifyIdentity`), `fetchBook` (`/api/book/`, optional currency and type filters, a `404` with `not_found` being an empty book) and `fetchLimits` (`/api/limits/`).
- `FederationBookReader(transport)` asks every coordinator at once: `requestAll` returns one future per coordinator, `read` waits and merges them into a `FederationBook` with one outcome per coordinator and every valid `PublicOrder`, tagged with its coordinator, by coordinator then id.
- Nothing is trusted: a body above `CoordinatorReadBounds`, a non-JSON body, an unexpected status or an invalid `/api/info/` field fails that one request with a `CoordinatorFailure`; an invalid book order or limits entry is dropped alone and counted (`droppedOrders`, `droppedEntries`). No failure and no `toString()` carries coordinator text.
- Tests run offline on responses recorded from the live federation: `test/fixtures/coordinator/README.md`.
